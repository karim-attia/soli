## Description

At WWDC26 (session 205 "Enhance your presence on the App Store") Apple introduced **creative assets**: optional marketing images/videos, separate from screenshots, that App Store Connect accepts since **2026-10-05** (together with the new **Asset Library** and **product page preview**). They show only on **iOS/iPadOS 27+**; older OSes keep showing screenshots.

Placements:

- **Search results** card: replaces the 3 small screenshots in search. This is where solitaire apps compete, so it's the most valuable slot.
- **Product page header**: big hero banner at the top of the product page.
- In-App Event cards, custom product pages / PPO, Apple Ads (the last two are irrelevant for Soli: no ads budget, too little traffic for PPO).

Approved assets can be swapped between header/search later **without a new review**, and they're submitted standalone (no app version bump needed).

### Icon research (round 3)

- `.icon` = folder with `icon.json` + `Assets/` (SVG/PNG). Canvas 1024. Background is the document `fill`, NOT a layer image. Max 4 groups, rendered back-to-front as glass layers. Schema is undocumented (reverse-engineered): top-level `fill`, `groups[]`, `supported-platforms`; group: `name`, `layers[]`, `lighting` ("individual"|"combined"), `specular`, `blur-material`, `translucency {enabled,value}`, `shadow {kind: neutral|layer-color|none, opacity}`; layer: `name`, `image-name`, `glass`, `hidden`, `opacity`, `fill`, `position {scale, translation-in-points}`. Any scalar has a `-specializations` array form `[{value},{appearance:"dark",value},{appearance:"tinted",value}]`. Colors are strings like `"display-p3:r,g,b,a"` / `"extended-gray:w,a"`. Examples: https://github.com/peterpoliwoda/icon-composer-template, https://lore.proxmox.com/all/DDWMW3GQP9PN.CBBJLTQ7RPK5@proxmox.com/t
- Gotchas: no full-canvas `<rect>` in layer SVGs (kills the glass); plain paths/fills only (no filters/masks/text); blur and glass are mutually exclusive on a layer; set an explicit `tinted` fill (mono from a dark green palette comes out muddy).
- Icon Composer 2.0 is at `/Applications/Xcode.app/Contents/Applications/Icon Composer.app`. Validate: `xcrun actool /ABS/PATH/assets/app.icon --compile /tmp/out --app-icon app --platform iphoneos --minimum-deployment-target 16.4 --output-format human-readable-text`.
- Expo SDK 58: `"ios": { "icon": "./assets/app.icon" }` (string only). Prebuild copies it to `ios/Soli/app.icon`, deletes `AppIcon.appiconset`, sets `ASSETCATALOG_COMPILER_APPICON_NAME = app`. Root `icon` PNG still feeds Android/splash. iOS < 26 gets a flattened icon generated by actool; community reports of broken back-deploy (missing background on 16.4) → must check an iOS 17/18 sim. Xcode 26.5 actool crashes on `.icon` (expo/expo#46121); local Xcode 27.0 is fine; check EAS image ≥ 26.6.
- Android: `android.adaptiveIcon.monochromeImage` supported (white silhouette, alpha, content inside the central 61%). Today `adaptive-icon.png` == `icon.png` (opaque), so `backgroundColor #0b8b3c` never shows.
- Design assessment: flat, centered, no baked shadows (good). Weak: stripes crossing the spade get busy rims at small sizes; thin black stem spike; black disappears in dark/tinted; gold on green ≈ 3:1 (OK for shapes). Refinements: layer it (spade group + stripes group floating above), thicker/rounded stem + rounded tips, explicit mono.

### Glyph size (round 5, researched 2026-10-17)

The glyph is not round: its farthest points from the canvas centre are the stripe corners (311.6 px at scale 1 on the 1024 canvas; axis extent 280 px; glyph bbox 49% of the canvas).

| Scale | Farthest point (px / dp of 108) | Glyph bbox | Android margin to 33 dp safe zone / 36 dp visible circle |
|---|---|---|---|
| 0.80 | 249 / 26.3 | 44% / 47 dp | 6.7 dp / 9.7 dp |
| **0.85 (Android, new)** | 265 / 27.9 | 46% / 50 dp | **5.1 dp / 8.1 dp** |
| 0.90 (Android, old) | 280 / 29.6 | 49% / 53 dp | 3.4 dp / 6.4 dp |
| 1.00 (iOS, old) | 312 / — | 49% | — |
| **1.15 (iOS, new)** | 358 / — | 57%, 190 px from the edge | — |

**iOS → `IOS_GLYPH_SCALE = 1.15`** (Karim liked 1.15x). Apple publishes no numeric glyph size: the HIG says "Keep primary content centered to avoid truncation when the system adjusts corners or applies masking", "you don't need to fill the entire icon canvas with content", "The system masks all layer edges", and refers to the grids in the Design Resources templates ([HIG App icons](https://developer.apple.com/design/human-interface-guidelines/app-icons)). Icon Composer's own guidance is to keep artwork 1:1 and set layout (x, y, scale) per layer in the inspector ([Creating your app icon using Icon Composer](https://developer.apple.com/documentation/xcode/creating-your-app-icon-using-icon-composer)). Empirical reference: Apple's iOS 26 icons on the simulator fill 65–85% of the tile width (Messages 0.77, Safari 0.81, Files 0.81, Preview 0.84, Fitness 0.84, Contacts 0.79; Soli before: 0.46), so 1.15x (0.57) is still on the conservative side; the farthest point stays 190 px from the edge, far from the ~22% corner radius and the glass rim. Mechanism: per-layer `position.scale: 1.15` in `icon.json` (verified: actool's flattened fallback scales about the canvas centre and matches `compose(scale=1.15)` pixel-for-pixel in stripe position), plus the same affine scale for the flat `icon.png`.

**Android → `ANDROID_FOREGROUND_SCALE = 0.85`** (was 0.9). Spec: layers 108 dp, inner 72 dp visible, 66 dp safe zone that no OEM mask clips, logo "at least 48x48 dp … must not exceed 66x66 dp" ([Adaptive icons](https://developer.android.com/develop/ui/views/launch/icon_design_adaptive); `SAFEZONE_SCALE = 66/72`, `EXTRA_INSET_PERCENTAGE = 1/4` in [AdaptiveIconDrawable.java](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/graphics/java/android/graphics/drawable/AdaptiveIconDrawable.java)). Keylines inside the safe zone (Nick Butcher, Google Design, via the [sspai translation](https://sspai.com/post/40223); the Medium original returns 403): circle 52 dp, square 44 dp (r 4), rectangle 52x36 dp; masks are convex with centre-to-edge ≥ 33 dp; "place the most important elements within the safe zone, as far as possible from the mask edge". At 0.85 the stripes are 52 dp long (= the keyline long side), the glyph bbox is 50 dp (≥ 48), and the stripe corners sit 5 dp inside the safe zone / 8 dp inside the visible circle; 0.9 left only 3.4 dp, which is not "clearly inside". History: 7056f74 (2025-11-09) fixed stripes clipped by circular launchers; the cause was that the opaque full-square `icon.png` was used as the foreground (glyph 417 px from centre on a 1024 scale, beyond the 341 px visible circle), the fix padded the whole square to 74.5%. Play Store 512 px icon: full square, Play applies a 30%-radius mask, "don't force your logo to fit the full asset space, use the keyline grid" ([Play icon specs](https://developer.android.com/distribute/google-play/resources/icon-design-specifications)); the flat `icon.png` at 1.15 fits that.

**Themed / monochrome icon → same 0.85.** The docs only ask for the mono layer to be centred in the 66 dp safe zone (no smaller inner size; the "~48 dp" idea is the minimum logo size, not a mono rule). Launcher3 renders the `<monochrome>` layer with the foreground's 108→72 mapping (`MonoIconThemeController.ClippedMonoDrawable = InsetDrawable(base, -getExtraInsetFraction())`, [source](https://android.googlesource.com/platform/frameworks/libs/systemui/+/refs/heads/main/iconloaderlib/src/com/android/launcher3/icons/mono/MonoIconThemeController.kt)), so no separate mono scale constant.

Comparison sheet: session scratchpad `icon/final/glyph-size-comparison.png` (iOS squircle 1.0 vs 1.15; Android 0.9 vs 0.85 under circle / squircle / rounded square / teardrop with the 66 dp + 72 dp circles; themed light/dark + raw mono; splash preview; small sizes), `icon/final/actool-scale-check.png` (position.scale honoured by actool).

## Intermediary learnings

- Glyph size (2026-10-17): Icon Composer's per-layer `position.scale` is honoured by actool's flattened fallback and scales about the centre of the layer's 1024 image (= canvas centre), so four identical per-layer scales equal one composition scale; the SVGs stay the measured 1:1 artwork and the inspector shows the real value (preferred over baking the scale into the path coordinates). Headless Chrome (142) intermittently exits 2 after writing the screenshot ("Teardown watchdog expired"), so `check=True` was wrong; success = output file exists. Apple publishes no numeric glyph-size rule for app icons; measuring Apple's own iOS 26 icons on the simulator (65–85% of the tile width) is the practical yardstick. Android's only numbers are 108/72/66 dp + the 48 dp minimum logo; the 52/44/52x36 dp keylines are from Google Design (Butcher), not the official docs.

- Icon (2026-10-17): the original spade is NOT one circle per lobe. Each lobe is a "shoulder" circle (r≈117.5, centre CX±87.3/569.5) with a smaller bottom circle (r=104, centre CX±100/574) internally tangent to it; the cusp of the bottom circles (y=602.6) is exactly where the stem apex sat (605). Straight sides from the tip (515.5, 246) are tangent to the shoulder circles. Stripes: 584×52.4 px at −43.62°, centres (461.9, 455.7) / (506.6, 504.9), 14 px gap. Stem: 203 px base, ~22 px neck, flare meets the base at ~22° (not tangentially, so a base fillet is pointless).
- The whole art sits 3.5 px left of the canvas centre (CX = 515.5); kept, since the stripes shift visual mass up-left anyway.
- `icon.json` schema confirmations from actool: top-level `fill-specializations` (default + `dark`) is accepted; per-layer `fill-specializations` with `"automatic"` + `tinted` solid works; `extended-srgb:r,g,b,a` and `extended-gray:w,a` color strings; a stray `README.md` inside the `.icon` is tolerated (kept outside anyway).
- Headless Chrome (`--headless=new --screenshot --default-background-color=00000000`) is a fine SVG rasterizer when rsvg/cairosvg/ImageMagick are missing; alpha survives.
- Android themed icon: later layers REPLACE earlier alpha (PIL `Image.composite` with coverage as mask) so stripes read as lighter bands over the spade instead of summing to opaque.

- Store art must not live under `assets/` (was bundled via `assetBundlePatterns: ["**/*"]`; the parallel SDK 58 upgrade (A4) removed that key, but store art still doesn't belong in the app's assets folder).
- Variant B: the circular mask radius must stay below half the displayed screenshot width (2568/2 = 1284 px) or the circle's sides get cut flat.

- Apple uses the literal term "creative assets"; they're **optional** and iOS 27-only, nothing is mandatory except iPhone Duo screenshots (April 2027) and the iOS 27 SDK (April 2027).
- Mockup round 1 (2026-10-17):
  - Rendering pipeline that works: author the creative as one `<div class="cre">` in a fixed 5244x2950 coordinate system, scale it with `transform: scale()` for the review page, and extract the same markup into a render-only HTML for `Google Chrome --headless=new --window-size=5244,2950 --screenshot --virtual-time-budget=10000 --hide-scrollbars --force-device-scale-factor=1`. Output is exactly 5244x2950; alpha is stripped losslessly with PIL (`convert("RGB")`), not via a JPEG round trip.
  - Headless Chrome clamps the window to a 500 px minimum width, so phone-width (400 px) screenshots of the review page are misleading; the layout itself has no horizontal overflow.
  - Screenshot felt is `#6B8E5A` (lighter than the icon green `#416F57`). Using a darker felt (`#3C6A52` to `#2E5542`) behind the phones makes the boards pop; using the same green would merge them.
  - The 1284 px screenshots are sharp enough for phone frames at ~1150 px wide (variant A). Variant B scales the spirograph frame 2x, which is visibly soft at 1:1; a final B would need a 2x capture (iPad sim or 3x-scale iPhone).
  - Crop math for the universal 16:9 asset: the 3:2 search card loses 410 px on each side, the 21:9 header loses 351 px top and bottom; the intersection (4424x2248, centered) is the working safe area. Apple's template in ASC may be tighter; verify in the product page preview before finalizing.
  - Icon geometry measured from `icon.png` (1024 canvas): spade bbox x316-716 / y248-676, stem x416-616 / y608-748, two 52 px stripes at about -44 degrees centered near (462,456) and (506,506). The SVG recreation in the mockup is close but not the source art; the `.icon` should be built from the original layered file.
