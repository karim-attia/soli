### SDK 58 React Native Notes (RN 0.86 -> 0.88, skipping 0.87)

- Package: `react-native`
- Retrieved: 2026-10-17
- Primary docs:
  - https://reactnative.dev/blog/2026/08/11/react-native-0.87
  - https://reactnative.dev/blog/2026/10/19/react-native-0.88
  - https://expo.dev/changelog/sdk-58
  - https://reactnative.dev/docs/strict-typescript-api

#### Target facts

- Expo SDK 58 pins `react-native@0.88.0` (stable on npm 2026-10-15 14:08 UTC). SDK 57
  skipped nothing; SDK 58 skips RN 0.87, so both release notes apply.
- Hermes V1 is the engine (`260318099.0.4`); the Hermes V1 memory regression from
  RN 0.86.0/0.86.1 is fixed.
- Toolchain minimums from RN 0.87: Node 22.13+, Kotlin 2.0+, `compileSdk`/`buildTools` 37,
  AGP 9 supported (default in the SDK 58 template), Metro 0.87.

#### RN 0.87 breaking changes and whether Soli is affected

| Change | Soli |
| --- | --- |
| Strict TypeScript API is the default (`react-native/Libraries/*` deep imports no longer typed) | Not affected: no deep imports in `app/`, `components/`, `src/`; `expo/tsconfig.base` already set `customConditions: ["react-native"]` |
| `InteractionManager` removed | Not used (`expo-router@57` used it internally; `58` does not) |
| `Touchable` root export, `Modal animated`, `StatusBar backgroundColor/translucent/networkActivityIndicatorVisible`, `NativeMethods` types, boolean `keyboardShouldPersistTaps` removed | Not used (`StatusBar` comes from `expo-status-bar`) |
| `useColorScheme()` returns `ColorSchemeName \| null`, never `'unspecified'` | Already typed for `null` (`app/_layout.tsx`, `components/Provider.tsx`, `FeltBackground.tsx`, `useKlondikeGame.ts`) |

#### RN 0.88 notes

- "No user-facing breaking changes" (third release in a row).
- W3C `EventTarget` dispatch is on by default; `ScrollView` programmatic scrolls no longer
  cancel touches in enclosing scroll views; variable font support; `ArrayBuffer` for Java
  TurboModules.
- iOS: UIKit scene life cycle (`SceneDelegate`) is generated by Expo prebuild; cold-start
  deep links route through it (smoke `yarn deeplink --ios --cold`).
- Runtime deep imports that third parties still use exist in 0.88:
  `Libraries/Renderer/shims/ReactFabric.js` (`@tamagui/portal`, wrapped in try/catch) and
  `Libraries/Utilities/codegenNativeComponent.js` (`react-native-svg`).
  `Libraries/Interaction/InteractionManager.js` is gone.

#### Expo-specific upgrade rule

Let `npx expo install --fix` pin `react-native`; never bump it independently of the Expo
SDK line. Native validation (fresh iOS simulator build and Android release build) remains
mandatory after any RN change.

## Target facts

- Soli enters the SDK 57 upgrade on `react-native@0.85.3`.
- Expo SDK 57 maps to React Native `0.86`.
- npm metadata reports `react-native@0.86.0` as the latest stable release.
- React remains `19.2.3` across Expo SDK 56 and SDK 57.
- Expo's latest SDK matrix keeps the minimum Node.js version at `22.13.x`.

## React Native 0.86 notes relevant to Soli

- React Native 0.86 has no user-facing breaking changes from 0.85.
- The release focuses on Android 15+ edge-to-edge fixes, React Native DevTools
  improvements, rendering/layout/animation fixes, accessibility fixes, and Android
  input/navigation/image fixes.
- Deprecations to watch for in app or dependencies:
  - `ViewUtil.getUIManagerType`
  - the second argument of `AppRegistry.setComponentProviderInstrumentationHook`
- Android BackHandler behavior changed only by adding an event object argument and fixing
  callback re-registration on API 36+. Existing callbacks that ignore the argument should
  continue to work.
- Safe areas, status/navigation bars, modals, keyboard behavior, Android back behavior,
  and animation-heavy gameplay should be smoke-tested on fresh native builds.

## Expo-specific upgrade rule

For Soli, do not independently pin React Native outside the Expo SDK 57 matrix. Let
`npx expo install expo@^57.0.0 --fix` align the supported RN version and then validate
with Expo Doctor plus native builds.

For Expo projects, React Native's own upgrading docs point back to the Expo SDK
upgrade walkthrough. Do not independently pin a React Native version outside the SDK
matrix unless there is a documented Expo-supported reason.

## Repo usage notes

- Soli no longer has a direct `StyleSheet.absoluteFillObject` usage in `app`, `src`, or
  `components`; current hits use the supported `StyleSheet.absoluteFill`.
- Soli uses `jest-expo`, and `@react-native/jest-preset@0.85.3` is installed because
  `jest-expo` needs the extracted RN 0.85 preset package.
- Test animation-heavy flows after upgrade because the new animation backend can
  affect gameplay feel even when APIs compile.
- RN 0.86 release notes say the upgrade from RN 0.85 should not require app-code changes,
  but Soli should still validate safe areas, BackHandler, modals, and Android 15+
  edge-to-edge behavior when planning SDK 57.

### `Share` (added 2026-10-12)

- Source: https://reactnative.dev/docs/share (read 2026-10-12) +
  `node_modules/react-native/Libraries/Share/Share.js` (0.86).
- `Share.share(content, options?)` → `Promise<{ action, activityType? }>`. iOS resolves with
  `Share.sharedAction` or `Share.dismissedAction`; **Android always resolves with
  `sharedAction`** (no dismiss signal). Rejects only on native failure — Soli treats the call
  as fire-and-forget and devLogs a rejection.
- `content`: at least one of `url` / `message`. **iOS** shares both as separate activity
  items (`url` gets the link preview, URL-only targets such as Reminders still work);
  `title` is the iOS subject-ish title. **Android** reads only `message` (+ `title` for the
  chooser) — a `url` field is ignored, so put the URL inside `message` there. Hence the
  platform split in `app/(tabs)/history.tsx` `handleShare`.
- `options`: `dialogTitle` (Android chooser title), `subject` (iOS mail), `excludedActivityTypes`,
  `tintColor`, `anchor` (iPad popover) — all optional, none used.
- "Some share options will not appear or work on the iOS simulator" — Messages/Mail are
  missing there; Copy / Notes / AirDrop still show, enough to verify the payload.
