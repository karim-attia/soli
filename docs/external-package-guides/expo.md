#### Official upgrade flow (as run for Soli)

```sh
npx expo install expo@~58.0.12 --fix   # newest age-gate-eligible patch on 2026-10-17
npx expo install --check
npx expo-doctor@latest
rm -rf ios android                     # CNG output; regenerated by the next build
```

Age gate rule of thumb: the gate only bites exact pins and `expo install`'s own
`latest` lookup. Tilde ranges written by `expo install --fix` (for example
`expo-router ~58.0.21`) resolve to the newest eligible patch automatically.

#### SDK 58 changes relevant to Soli

- Hermes V1 memory regression: `expo@57.0.0-57.0.8` (RN 0.86.0/0.86.1) inflate memory when
  Reanimated/Worklets are imported; fixed in `expo@57.0.9` and carried into SDK 58. Soli
  shipped `57.0.4`, so SDK 58 is also a memory fix. Upstream guidance: do not toggle Hermes
  V1 away from the SDK default and do not use Worklets bundle mode as a workaround.
- iOS: RN 0.88 / SDK 58 adopt the UIKit scene life cycle (`SceneDelegate.swift`,
  `UIApplicationSceneManifest`) in the generated project. Deep links on cold start go
  through the scene delegate; smoke `Linking.getInitialURL()` paths after the upgrade.
- Android: R8/minify is now on by default for release builds
  (`android.enableMinifyInReleaseBuilds=true` in the template). `yarn release` and the
  store AAB both run R8. Opt-out path if it strips something: `expo-build-properties`
  with `android.enableMinifyInReleaseBuilds: false`.
- `expo-sqlite` 58 removed libSQL (unused) and fixed a `SQLiteStorage` first-run migration
  race. `expo-linking` 58: `Linking.parse()` no longer double-decodes (Soli uses `new URL`).
- Expo Router 58 reworked its navigation core; see `expo-router.md`. Expo UI 58 changed
  `<Host>` alignment on iOS; see `expo-ui.md`.
- Optional SDK 58 features deliberately not adopted in the upgrade: Expo Modules 2.0
  (beta), Noxcturnal transformer, Gesture Handler hook API, `Stack.Toolbar`, Tamagui 3.
  Tracked in the upgrade plan's Follow-ups.
- **React Compiler is ON since 2026-10-18** (`app.json` → `expo.experiments.reactCompiler:
  true`, `infer` mode app-wide, every manual memo kept). Measured A/B on the Android phone
  (Release, 2 × 20-game playlists per config): janky 9.12 % → 8.14 %, p50/p90/p95/p99
  10/15/17/21 ms unchanged, PSS +2-6 MiB (inside run-to-run noise), 0 crashes, scrubber /
  celebration / hint / glow identical on both platforms. Numbers in
  `docs/product/next-steps-after-sdk-58/next-steps-after-sdk-58.md` ("S11 results").
  **Rollback = delete the `"reactCompiler": true` line**, then `rm -rf
  android/app/build/generated/assets/react/release` before `yarn release` (app.json is not
  an input of the Gradle bundle task, so the old bundle would be reused) — iOS re-bundles on
  every build. Reach: `babel-preset-expo` inserts `babel-plugin-react-compiler` (`target 19`,
  `panicThreshold none`) for app code only; 75 functions compile, 8 are skipped on deliberate
  render-time ref patterns (list in the same plan). Jest never sets `supportsReactCompiler`,
  so unit tests run uncompiled code. The Release Android bundle is Hermes bytecode — to prove
  the flag reached a build, export plain JS (`expo export:embed --platform android --dev
  false --minify false …`) and count `react.memo_cache_sentinel` (off: 2, on: 86).
- `expo.install.exclude` now lists only `typescript`. The `react-native-worklets`
  exclusion (SDK 57 `0.10.1` override) was removed because SDK 58 bundles `0.13.0`.

- Keep `@babel/core` and `babel-preset-expo` as explicit dev dependencies; review them

## SDK 57 notes relevant to Soli

- SDK 57 is a focused SDK 56 -> 57 upgrade that primarily brings React Native 0.86.
- Expo says the upgrade from SDK 56 / RN 0.85 should be straightforward because RN
  0.86 has no user-facing breaking changes, but Soli still needs fresh native builds.
- `expo prebuild` now clears and regenerates native `android` and `ios` directories
  by default. This matches Soli's generated/ignored native folder workflow; do not add
  tracked native project files.
- Expo Go for SDK 57 may not be available in all app stores immediately. Use dev or
  release builds for production-app validation.
- SDK 57 bundles newer animation/gesture packages: Reanimated 4.5, Worklets 0.10, and
  Gesture Handler 2.32.
- Known regression: Android Hermes V1 plus Reanimated can increase memory usage by
  25-30%. Worklets bundle mode is the documented workaround, but do not enable it
  without evidence in Soli.
- For SDK 56 and greater, `expo-build-properties` documents its iOS
  `deploymentTarget` plugin option as deprecated in favor of built-in
  `ios.deploymentTarget` app config. Prefer the built-in property if native checks pass.

## Repo usage notes

- Continue to prefer Expo/CNG tooling for native output.
- Keep `babel.config.js` and `metro.config.js` because Tamagui needs custom Babel and
  Metro integration.
- Do not opt into new Android edge-to-edge behavior or Worklets bundle mode as part of the
  baseline SDK 57 upgrade unless validation exposes a concrete need. (React Compiler was
  also held back here; it was measured and switched on 2026-10-18 — see the SDK 58 notes.)

## Upgrade Workflow (Official)
1. Upgrade Expo SDK package:
   - `npm install expo@^55.0.0` (or the equivalent package manager command).
2. Align dependency versions:
   - `npx expo install --fix`
3. Run diagnostics:
   - `npx expo-doctor`
4. Handle native project updates:
   - CNG projects: regenerate native directories.
   - Non-CNG projects: run `npx pod-install` and apply native diffs.
5. Follow SDK 55 changelog migration items.
